專案背景與定位

本專案是在先前 A/B 專案的爬蟲與資料結構化整理基礎上，全新升級的「網頁化自動部署管線」。 本系統旨在定時監控政府電子採購網勞務類標案，並藉由 Google Sheets API 實現雲端資料共同編輯與標記，接著將數據自動渲染成雙介面響應式 HTML 報告，最後透過本地 Git 工具自動推送至 GitHub Pages 雲端公開網站。

重要更新 ─ 網頁跨端實體物理隔離： 首頁 index.html (管理決策版) 與標案整理明細頁 tenders.html 已實行實體檔案物理隔離。首頁移除了可能暴露的詳細標案網址，並由 tenders.html 作為內部歷史公告入口，加強資訊安全防護。

工作管線 (Pipeline) 流程

專案的管線核心控制是由 tender_pipeline_master_c.py 主控，流程可區分為三大關卡、六個精細步驟：

步驟 1. PCC 政府採購網爬蟲與資料篩選
系統定時啟動 tender_scraper_api_c.py，透過網路要求取得政府採購網當日的勞務標案。利用正則表達式篩選出符合條件之標案，剔除不合適分類。
步驟 2. Google Sheets API 雲端比對與寫入
使用服務帳號憑證（credentials.json）連線至 Master Google 試算表。 如果是上午 (08:30) 模式，直接建立全新日期分頁並寫入；如果是下午 (17:40) 模式，則會拉取上午寫入之分頁，實施差分比對（Diff）。若下午比對發現無任何新增案件，主程式將以 Exit Code 3 中斷執行，不再往下執行網頁渲染與 Git 發布，節省 API 配額與伺服器資源。
步驟 3. 跨裝置響應式 HTML 報告渲染
主控腳本呼叫 test_screenshot_c.py，將試算表中整理好的今日標案與推薦卡片撈出，編譯為靜態 HTML。 渲染時會對關鍵字進行自動高亮標記，並同步儲存一份於本地永久備份資料夾 D:\標案網頁歷史備份 中。
步驟 4. 網頁物理隔離與手機版版面優化
HTML 首頁（index.html 管理決策版）與明細頁（tenders.html）實施物理隔離，保護網址鏈接。 響應式設計：寬度小於 768px 時，網頁自動隱藏寬大繁雜的 Table，改以流暢好滑的「凝聚型卡片直列列表」呈現，方便老闆在手機上極速過濾與閱讀。
步驟 5. 雲端 30 天滾動清理機制
程式在每次生成網頁時，會主動掃描雲端 report/tenders/ 底下的所有歷史 HTML 報告。凡建立時間大於 30 天之舊報告，程式會自動將其自雲端發布目錄中物理刪除，以落實 Git 倉庫輕量化，而本地的永久備份則不受此清理影響。
步驟 6. 本地 Git 推送與雲端靜態網頁發布
管線程式最後自動切換至 D:\03.AI\report 目錄，自動執行 git add . ➔ git commit -m "Auto-update..." ➔ git push origin main，將最新渲染之首頁與報告推播至 GitHub Pages。
Windows 工作排程器配置規範

為了確保地端排程在背景執行時，不會因為 Windows 繁體中文路徑 D:\03.AI 產生 Big5 (CP950) 與 UTF-8 編碼衝突，排程設定必須嚴格遵守以下三大鐵則：

重要！排程登錄三大技術鐵則：
  1. 無感直調模式 (No-Shell Direct Mode)： 排程 Action 的執行項目必須直接指定 python.exe，絕對不能透過 .bat 批次檔或 cmd.exe 當作媒介，因為 cmd.exe 載入中文路徑時 100% 會因 Big5 解碼失敗而崩潰。
  2. 注入 -X utf8 啟動引數： 在排程引數中，必須將 -X utf8 置於最前，強制 Python 解譯器使用 Unicode 處理所有路徑與 stdout 輸出。
  3. 排除重複垃圾排程： 排程註冊腳本執行前，會強制解註冊所有舊的、拼寫相近的歷史排程，統一命名為唯一的 TenderAutomation_C。
PowerShell 排程註冊核心代碼範本 (setup_tender_task_c.ps1)
# 1. 建立雙觸發器 (上午 08:30 與 下午 17:40)
$Trigger1 = New-ScheduledTaskTrigger -Daily -At "08:30"
$Trigger2 = New-ScheduledTaskTrigger -Daily -At "17:40"

# 2. 建立 Action (直接呼叫 Python 並注入 -X utf8 參數)
$Action = New-ScheduledTaskAction -Execute $PythonPath `
            -Argument "-X utf8 `"$ProjectScript`"" `
            -WorkingDirectory $ProjectDir

# 3. 建立電源與優先級設定 (允許電池執行、有網路時啟動)
$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries `
            -DontStopIfGoingOnBatteries -StartWhenAvailable -MultipleInstances Parallel

# 4. 以當前使用者身分登錄排程並強制覆蓋
Register-ScheduledTask -TaskName "TenderAutomation_C" `
    -Trigger $Trigger1, $Trigger2 -Action $Action -Settings $Settings -Force

核心執行原理
  • 輕量級 API 網頁爬取： 爬蟲使用 requests 以原生 HTTP GET/POST 封包直接向政府採購網進行篩選條件查詢，取代了肥大且易出錯的 Selenium 模擬瀏覽器，確保背景執行穩定且快速。
  • Google Sheet 動態儲存庫： 利用 Google Sheets 作為地端與雲端的中介資料庫，省去安裝大型 SQL 資料庫的繁瑣，同時方便管理者隨時進入試算表進行人工標註。
  • 差分增量檢查 (Diff-Check)： 每日下午執行時，系統會先抓取當日上午已寫入的標案案號列表，對最新爬網數據進行差分計算。僅當有「新增標案」時才觸發後續寫表與發布，否則以 Exit Code 3 優雅終止，節省 API 額度。
  • 跨裝置響應式渲染： test_screenshot_c.py 會自動讀取 Excel 數據並重新生成 index.html 與 tenders.html。利用 CSS Media Queries 技術實施桌機 Table 與手機凝聚卡片的無縫變換。

Google Cloud 服務憑證權限確認

本專案的 Google Sheets API 存取權限依賴專案根目錄底下的 credentials.json 金鑰檔案。

授權必做步驟：
  1. 開啟該 credentials.json 檔案，找到 "client_email" 欄位，複製其電子郵件地址（通常為 xxx@xxx.iam.gserviceaccount.com）。
  2. 登入 Google Sheets 網頁，開啟目標試算表。
  3. 點擊右上角「共用」，將複製的服務帳號 email 加入，並給予「編輯者」權限，即可確保地端程式正常讀寫雲端數據。
